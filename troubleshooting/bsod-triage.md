# 多 bugcheck 码蓝屏与硬冻结的分级排查

> 证据分级：本文结论标注为「实测」「推断（非确证）」「待确认」三档，不混写。凡标注为推断者，不得在后续引用中升级为确定结论。

## 问题

约三周观察窗口内，同一主机出现横跨多个互不相关子系统的故障：

| 形态 | 次数 | 特征 |
| --- | --- | --- |
| 蓝屏（有转储） | 3 | 三个互不相同的 bugcheck 码 |
| 意外关机 / 硬冻结（**无转储**） | 4 | 系统日志仅留 Kernel-Power 41 + 6008，无内核现场 |
| PCIe 可纠正错误 | 1 | WHEA-Logger ID 17 |
| 非致命内核挂起 | 3 | 活内核转储（LiveKernelReports） |

**症状指纹**（用于判断是否属同一类问题）：

| 指纹 | 说明 |
| --- | --- |
| 多个不同 bugcheck 码轮番出现 | 单一驱动缺陷通常反复产生同一个码；码不一致指向共享底层（硬件 / 固件 / 供电） |
| 存在无转储的硬冻结 | 连 bugcheck 都未能留下，说明内核未走到崩溃处理路径 |
| 崩溃发生在近乎空载时 | 未运行任何负载程序仍发生 TDR 蓝屏 |
| 时间跨度早于本次排查 | 首次观测之前即已有同类事件 |
| 默认转储配置不足 | 默认只存小转储（寄存器 ＋ 栈，缺驱动对象与内存现场），不足以定案 |

**症状形态本身就是证据**：「多个不同 bugcheck 码 ＋ 无转储硬冻结」这一组合，比任何单个转储更早地指向平台级不稳定，它决定了排查顺序应从平台（内存 / 固件 / 供电）开始，而非从某个具体驱动开始。

## 原因

分层判定，四档：已排除项（实测）、已确证项、推断（非确证）、尚未定案。

### 已排除项（实测）

| 项 | 实测值 | 结论 |
| --- | --- | --- |
| 磁盘 | 两块 NVMe：系统盘与数据盘；`HealthStatus=Healthy`、`Wear=0`、温度约 60 °C | 已排除 |
| 供电 | `PowerOnline=True`、电量 100 %、未充电未放电 | 交流供电正常 |
| 温度 | 双烤实测 GPU 69 °C / CPU 78 °C，未越上限；`Temp limit` 全程 0 次 | 散热非瓶颈 |
| 电池 | 设计容量与满充容量差约 0.3 % | 排除电池老化导致的供电不稳 |
| 显卡超频 | 核心 / 显存偏移均为空；未做降压 / 解锁 | 已排除超频因素 |

### 已确证项（实测）

1. **内存为混插**：两条 DDR5-5600 SO-DIMM 容量相同、均为单 Rank，但来自不同厂商 / 不同型号（`Win32_PhysicalMemory` 实测）。不同厂商 / 不同 die 的 DDR5 混插是已知的稳定性风险源，其症状形态正是「不同 bugcheck 码轮番出现 ＋ 无故硬冻结」。
2. **一组已卸载安全软件遗留的孤儿内核驱动正在运行**：本体程序已不存在、查不到卸载记录，但两个内核驱动仍被加载，其中一个是 `BOOT_START` 级别的早启动反恶意软件驱动。转储证据证实崩溃时它就在内核内存中。
3. **`0x116` 崩溃的肇事地址落在显示驱动区间内**（实测，但见限定）。
4. 显卡调节工具未套超频（与上表一致，此处仅作结论归档）。

### 推断（非确证）

1. **平台级不稳定**（依据见「问题」末尾）。
2. **内核中并存多组高权限 hooked 驱动，构成故障的背景条件。**可疑第三方内核驱动 ＋ 孤儿安全软件驱动 ＋ 游戏反作弊驱动 ＋ 显卡调节驱动 ＋ 主板厂商驱动同时驻留内核，共同构成「多个互不相关子系统随机出错 ＋ 硬冻结」的常见背景条件。此为**背景条件，不构成对任何单一模块的定罪**。
3. **内存混插仍在嫌疑名单，权重下降。**内存测试工具已全盘跑过两次无报错，且 32 GB 容量是强制需求，「拔掉一条」不能作为长期方案。保留的可能性是：混插仅在真实负载 / 温度条件下才暴露（测试工具的访问模式与真实负载不同），该假设只能靠单条 A/B 跑真实负载排除。
4. **相关性（非因果）**：孤儿驱动的文件创建时间与首轮硬件事件在时间上相邻，**属相关性，尚无因果证据**。

### 尚未定案

- 系统固件是否为最新版本未确认（现行为出厂固件；主板厂商官网当时返回 HTTP 403，需换途径核实）。
- 显卡驱动版本与 `0x116` 直接相关，但排查优先级排在内存之后。
- **悬案（明确记录，不编造解释）**：两次崩溃都落在执行「转储分析类动作」的时间窗内。该调试工具不接触显卡，**既不能证明相关、也不能证明无关**；两者的共同点是**持续的重磁盘 / 网络 I/O**。在内存问题排除前，不自动重跑该类分析。

转储模块表、bugcheck 参数定位、孤儿驱动实测清单见 [`raw/bsod-triage-evidence.md`](raw/bsod-triage-evidence.md)。

## 方法

### 已执行的处置

**① 开启完整转储取证能力**（全部可回滚）：

| 项 | 原值 | 现值 | 作用 |
| --- | --- | --- | --- |
| `CrashControl\CrashDumpEnabled` | `3` | **`7`** | 下次蓝屏留下带完整驱动栈的自动内存转储 |
| `i8042prt\Parameters\CrashOnCtrlScroll` | 不存在 | **`1`** | 硬冻结时可用 `右Ctrl + ScrollLock` ×2 强制触发 bugcheck 留转储 |
| `kbdhid\Parameters\CrashOnCtrlScroll` | 不存在 | **`1`** | 同上（USB 键盘路径） |
| 安装调试器（转储分析） | — | 已安装 | 转储分析 |

分页文件为 System 托管，自动内存转储具备写入空间；改动已逐项回读复核。

**② 清理遗留孤儿内核驱动**：删除早启动反恶意软件驱动（服务 ＋ 文件），另一个因模块仍在内存中而被占用，改为标记删除（`DeleteFlag=1` / `Start=4`）＋ 排入重启时删除，**必须重启才算完成**。执行前已全盘扫描同类内核服务，确认只有这两个（第三个匹配项实为显卡控制中心组件，属误匹配，未动）。

**③ 第二轮扫尾**：删除残留目录、注册表项与失效的防火墙规则，逐项回读确认已不存在。

备份与回滚集中于一处：`backups\<cleanup-stamp>\`（含注册表导出、驱动原件、目录备份、防火墙规则清单与逐条回滚说明）。

### 验证与判据

- **重启后观察 24 小时**：不再出现蓝屏 / 硬冻结 ⇒ 该组孤儿驱动为主要成因（或主要成因之一）。
- **仍崩溃** ⇒ 按剩余嫌疑继续排查：内存混插（单条 A/B 跑真实负载）→ 显卡驱动 → 系统固件 → 硬件。
- **无论以何种方式再次崩溃，取证均已就位**：自动内存转储已开启；硬冻结时可按热键强制触发 bugcheck 并留下完整转储。
- 转储分析命令见 raw 文件。

## 结果

观察窗尚未结束。当前状态：取证能力已就位、一组孤儿驱动已清理（待重启落地）、内存混插仍未排除。

### 回滚

| 项 | 回滚命令 |
| --- | --- |
| `CrashDumpEnabled` 恢复原值 | `Set-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\CrashControl' -Name CrashDumpEnabled -Value 3 -Type DWord` |
| `i8042prt` 的 `CrashOnCtrlScroll` | `Remove-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Services\i8042prt\Parameters' -Name CrashOnCtrlScroll` |
| `kbdhid` 的 `CrashOnCtrlScroll` | `Remove-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Services\kbdhid\Parameters' -Name CrashOnCtrlScroll` |
| 卸载调试器 | `winget uninstall Microsoft.WinDbg` |
| 恢复已删除的孤儿驱动与服务 | 见备份目录内的回滚说明（含逐条命令、注册表导出与驱动原件） |

### 可迁移结论

1. **结论必须分档留痕。**实测、推断与待确认混写，会让后续引用把推断当成实证。
2. **默认转储配置往往不足以定案。**只保留小转储时缺少驱动对象与内存现场，「分析转储」这条路本身走不通。
3. **批量删除前必须逐条检视命中项。**按关键字匹配会把名称近似的系统自带组件一并卷进来；只看命中数量、不看命中内容，迟早误删系统组件。
4. **已卸载软件的残留内核驱动是真实风险面**，尤其是早启动级别的反恶意软件驱动：本体已不存在，驱动仍在每次开机极早期加载，且不会被常规卸载流程清理。
5. **排查动作本身要避开高风险时间窗。**在根因未定（尤其是内存未排除）时执行持续重 I/O 的分析任务，会污染现场，使「动作」与「故障」在时间上纠缠、难以定性。
6. **症状形态本身是证据**（见「问题」末尾）。

### 已知限制

- **本机未留下过完整崩溃转储**：现有三个均为小转储；完整转储能力是本次改动后才具备的，对已发生事件的回溯能力有限。
- **待分析转储**三个；在内存问题排除前不自动重跑分析（见悬案）。
- **24 小时观察窗尚未结束。**
- **内存混插的定性不完整**：测试通过是实证，但测试工具的访问模式与真实负载不同；单条 A/B 实验因容量为强制需求而难以长期执行。
- **系统固件版本待核实**；**显卡驱动待评估**。
- 其中一次断电为**外部原因**，不计入本事故的故障统计。
- **排查分工约定（沿用）**：需要重启 / 进固件设置界面 / 拆机的操作（内存测试、单条 A/B、固件更新）需人工执行；需要软件层证据的操作（转储分析、驱动版本核对、事件日志提取）可自动化，但需避开内存未排除时的重负载时段。
