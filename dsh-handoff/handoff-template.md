## 6. 机制说明

| 环节 | 机制 |
| --- | --- |
| 数据源唯一 | 未决事项、结论、挂起事项只记录在状态文件中，本文件由脚本渲染，避免多处事实冲突 |
| 事实不依赖人工陈述 | 插件是否加载、开关状态、任务是否存在、引用路径是否有效、文件改动时间，均由核对脚本实测并写入核对时间戳 |
| 漂移自动告警 | 本文件早于任一档案、核对超出有效期、引用路径失效、插件缺失、开关关闭、任务丢失等情况均会产生告警，并写入上文的核对告警栏 |
| 定期自检 | 计划任务按固定周期以只读方式执行核对（日志写入 `handoff-check.log`），该任务不会修改本文件 |
| 会话纪律 | 会话开始时执行一次 `-Check`；结束前按「修改状态文件 → 渲染 → 复核」的顺序执行。顺序颠倒时脚本会报告本文件早于状态文件 |
| 编码约束 | 核对脚本正文必须为纯 ASCII：计划任务环境使用 Windows PowerShell 5.1，会将无 BOM 的 UTF-8 文件按 ANSI 解析，导致解析失败。所有中文文案仅存在于本模板中 |
| 区域标记 | 形如 `{{#N}}…{{/N}}` 的段落按位掩码显示。各位含义：`1` 存在告警、`2` 任务全部正常、`4` 皮肤被关闭、`8` 启动清单缺项、`16` 自检失败、`32` 状态漂移、`64` 加载脚印过期、`128` 全部正常 |
