# 事故复盘：无窗口启动器被编译为控制台子系统，导致周期性弹窗并抢占焦点

> 事故编号：INC-2026-0918-02 ｜ 发生日期：2026-09-18 ｜ 状态：已修复并在生产条件验证
> 影响面：任务计划每次触发时，于当前主显示器闪出一个控制台窗口（存活约 59 ms）并抢占前台焦点，打断鼠标操作
> 与 INC-2026-0918-03（蓝屏 / 硬冻结）同一日晚发生，但**两者无因果关系，不得合并归因**

---

## 1. 摘要

辅助工具 `run-hidden.exe` 被编译为**控制台子系统**程序（PE `Subsystem = 3`），与其名称所声明的行为相反，它并不隐藏自身窗口。具体机制：该工具由任务计划经 `svchost`（无控制台）拉起，Windows 检测到「控制台程序 + 父进程无控制台」后，为该进程自身分配了一个新的控制台窗口。源码中的 `CREATE_NO_WINDOW` 仅作用于**由其创建的子进程**，对自身无效。

后果：看门狗任务每次触发（周期 5 分钟）即在当前主显示器上闪出一个黑色控制台窗口，存活 59 ms，并抢占前台焦点，造成鼠标运动被打断。

处置：以 `/target:winexe` 将该工具重新编译为 GUI 子系统程序（PE `Subsystem = 2`）。GUI 子系统进程不分配控制台，窗口无从产生；其子进程仍由 `CREATE_NO_WINDOW` 保证无窗口。修复已在生产条件（任务计划拉起）下完成 A/B 验证，任务功能未被破坏。

## 2. 现象与症状指纹

**操作者原始描述**：外接屏幕在闪烁，表现为**突然弹出一个窗口并立即关闭**，持续时间短到无法看清窗口标题，但**会打断鼠标运动**。

上述三条特征（周期性 / 窗口存活极短 / 抢占前台焦点）已足以将问题指向「有进程周期性弹窗并抢焦点」，而非显示链路故障。

**症状指纹**（用于下次快速识别同类故障）：

| 指纹 | 观测值 |
| --- | --- |
| 可见窗口类名 | `ConsoleWindowClass` |
| 窗口进程 | 声称「隐藏窗口」的启动器可执行文件本身，而非其子进程 |
| 窗口存活时长 | 约 59 ms（不足以看清标题） |
| 触发周期 | 与任务计划的重复间隔一致（本例 5 分钟） |
| 伴随影响 | 前台焦点被抢占，输入 / 鼠标操作被打断 |
| 任务侧指标 | 任务的 `rc=0`，且看门狗日志正常写入 —— **任务侧指标完全正常，不能作为排除依据** |

## 4. 根因

**根因**：可执行文件的 PE 子系统类型与其宣称的行为不符。

1. 旧版 `run-hidden.exe` 的 PE 头为 `Subsystem = 3 (Console)`。
2. 任务计划由 `svchost` 拉起，而 `svchost` 没有控制台。
3. Windows 对「控制台子系统程序 + 父进程无控制台」的组合，会为该进程**自身**分配一个新的控制台窗口。
4. 源码中的 `CREATE_NO_WINDOW` 只传递给它创建的子进程，**管不到它自己**。

**因此：「隐藏窗口」必须连同自身一起隐藏。父进程自身的 PE 子系统决定了它会不会被分配控制台；要获得真正无窗口的启动器，必须编译为 GUI 子系统。**

PE 头实测对照：旧产物 `Subsystem = 3 (Console)`；新产物 `Subsystem = 2 (GUI)`。

## 5. 证据链

使用自制探测器 `flash-hunter.ps1` 抓取现场。该探测器的设计要点：枚举**可见顶层窗口**（不只监视前台窗口，否则会漏掉「已弹出但未抢到焦点」的窗口）、订阅 WMI `Win32_ProcessStartTrace` 记录进程启动、以 40 ms 周期轮询、并按窗口坐标判定所在屏幕。

捕获记录如下：

```text
2026-09-18 20:12:37.977  WIN+  hwnd=0x100242 pid=8272(run-hidden) class=ConsoleWindowClass
                                title=%USERPROFILE%\.dsh\run-hidden.exe
                                rect=230,230,991x518  @EXTERNAL(primary)
2026-09-18 20:12:37.981  FG    抢走前台焦点
2026-09-18 20:12:38.036  WIN-  (closed)  存活 59 ms
```

关键取证在于**两条独立证据链的时间对齐**：探测器捕获的窗口出现时刻（20:12:37.977）与看门狗任务的 `LastRunTime`（20:12:37，`rc=0`）一致，从而将窗口归属到该任务，而非其他周期性进程。

## 8. 经验教训

1. **「隐藏窗口」必须覆盖自身**。`CREATE_NO_WINDOW` 只作用于子进程；父进程自身的 PE 子系统决定了它是否会被分配控制台。实现无窗口启动器必须编译为 GUI 子系统。
2. **验收判据必须是「屏幕上有没有东西」，不能是「任务返回码为 0」**。该启动器 09-18 12:18 上线时只验证了 `Result=0` 与心跳正常，因此缺陷潜伏了约 8 小时。**脚本自行打印的成功信息不构成证据。**
3. **复现必须还原真实条件**。从**有控制台**的父进程（交互式 PowerShell）启动时，子进程继承控制台、**不会新建窗口** —— 测试环境正好把缺陷隐藏起来；只有由**任务计划（`svchost`，无控制台）**拉起才能复现。本事故的第一次 A/B 试验即失败于此。
4. **偶发弹窗的通用抓法**：使用 `flash-hunter.ps1` —— 枚举**可见顶层窗口**（不能只监视前台窗口，否则会漏掉「已弹出但未抢到焦点」的窗口）＋ 订阅 WMI `Win32_ProcessStartTrace` 记录进程启动 ＋ 40 ms 轮询 ＋ 按窗口坐标判定屏幕归属（主屏 X 坐标 ≥ 0）。
5. **不得以 `.bak` 后缀命名可执行文件的备份**。此类文件被双击或被 ShellExecute 调用时会弹出「选取应用」对话框（实测发生，且弹窗残留在操作者屏幕上，需手动终止 `OpenWith.exe`）。

## 9. 已知限制与未决项

- **遗留隐患**：启动游戏所触发的辅助工具拉起路径（辅助程序任务的执行路径指向 `$env:DATA_DIR\<HELPER_DIR>\<HELPER_EXE>`）尚未包裹，启动游戏时会弹出一个控制台窗口。**待操作者决定**（包裹后将隐藏该工具的控制台，其图形界面不受影响）。
- **原因未查明的特殊现象（悬案，不编造解释）**：在 PowerShell 中用 `&` 直接调用 GUI 子系统可执行文件时，功能测试不通过（`$LASTEXITCODE` 为空、子进程无输出）；而生产路径（由任务计划拉起）实测正常。两者差异的原因未查明。
- 本次修复仅验证了「窗口是否出现」与「任务功能是否正常」，未对旧版可能在其他宿主环境（如带控制台的交互式调用）下的行为做穷尽枚举。
