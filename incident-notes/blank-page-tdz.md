# 事故复盘：客户端整页不渲染（TDZ 型 ReferenceError）

> 事故编号：INC-2026-0918-01 ｜ 发生日期：2026-09-18 ｜ 状态：已修复并验证
> 影响面：桌面客户端渲染层（整个页面空白，用户无法操作）
> 复现环境：Windows 11 ／ DSH 0.1.5-rc.2（本机部署）

---

## 1. 摘要

2026-09-18 20:22，本机部署的客户端出现**整页不渲染**故障。根本原因已定位并实测复现：一次自动补丁流程向 `dsh-client-ui-layout` 的 `AppFrame` 组件注入了两行代码，插入位置位于 `const narrow = …` 语句**之前**，触发暂时性死区（Temporal Dead Zone，下称 TDZ）错误 —— `ReferenceError: Cannot access 'narrow' before initialization`。`AppFrame` 为三列框架的根组件，其每次渲染均抛出异常，导致整棵渲染树无法挂载，页面呈全白状态。

该缺陷未被补丁流程自带的语法检查拦截：`node --check` 退出码为 0，因为 TDZ 属于**运行期**错误，代码在语法上完全合法。

处置结论：肇事的移动端侧栏补丁（记录中称「补丁 B」）已退役，仅保留安全补丁（「补丁 A」）并重新施加；新增常驻自检脚本用于防止回归。用户侧的卸载重装操作虽恢复了服务，但并非必要 —— 该缺陷属**文件级**问题，直接移除补丁即可恢复。

## 2. 现象与症状指纹

**现象**：浏览器访问客户端页面时，页面完全空白，无任何渲染内容，用户无法进行任何操作。

**症状指纹**（用于下次快速识别同类故障）：

| 指纹 | 观测值 | 说明 |
| --- | --- | --- |
| 整页空白 | 渲染内容为空 | 非局部组件失效，而是根组件抛出异常 |

| 用户侧表现 | 输入无响应 | 表现为会话被静默终止，而非报错弹窗 |

## 4. 根因

**根因**：补丁 B 的注入位置越过了变量声明，形成 TDZ 引用。

注入后的真实代码形态如下：

```js
// dsh-client-ui-layout/lib/client.js，函数 AppFrame({ useStore, useSessions, ... })
			}, [actions]);
/* local patch 2026-09-16: keep the left sidebar collapsed on a narrow viewport */
if (narrow) layoutInfo.narrowExpanded = false;          // ← 先引用 narrow
			const narrow = viewport < SIDEBAR_AUTO_COLLAPSE;  // ← 后声明（同一函数作用域）
```

机制说明：`const` 声明在同一函数作用域内被提升但不初始化，在初始化之前访问该绑定即抛出 `ReferenceError`。该异常发生在 `AppFrame` 的渲染路径上；`AppFrame` 是三列框架的根组件（同文件内注释为 `/** The three-column frame (see module doc). */`），根组件抛出后整棵渲染树无法挂载，页面呈全白。

**为什么历史版本未暴露该缺陷**（**属推断，非实测** —— rc.1 的对应文件已被升级覆写，无法回读验证）：补丁 B 的锚点字符串在 rc.1 的文件结构中落在无害位置；09-17 22:43 的升级将该补丁洗掉，直至 09-18 20:22:16 又被重新施加到 rc.2 的新结构上。**同一锚点字符串，在不同版本的文件结构中可能成为缺陷。**

**补丁 A 的保留依据**：补丁 A 注入于 `retainAccountKeys: (d, workspaceKeys) => {` 内部，其中 `d` 为形参，作用域安全。其作用是修复旧版本视图状态缺失字段导致的问题 —— 旧版本写入的 `dsh.workspace.view.v5` 缺少 `sessionUpdatedAtByAccount`，引发 `Object.entries(undefined)` 并使侧栏崩溃。同一份自检报告实测该补丁已丢失（命中数 0），故本次重新施加并回读确认（位于第 216–220 行，`node --check` 退出码 0）。

## 7. 回滚方案

- **恢复旧行为（不推荐）**：将 `RETIRED-apply-mobile-sidebar-patch.ps1.DO-NOT-RUN` 改回 `.ps1` 扩展名后执行。**注意：该补丁即本次白屏事故的成因。**

- **家目录备份**：备份目录内的家目录副本（401 MB）为**崩溃前**状态。**未做改动，亦不建议以其覆盖现行家目录** —— 本次故障不在家目录内，覆盖只会丢失 09-18 已有的档案更新。

## 8. 经验教训

1. **语法检查不能替代运行期验证**。`node --check` 通过不代表代码可运行；TDZ、未定义引用、类型错误均属运行期问题。凡涉及在 `const` / `let` 声明之前引用同名变量的补丁，一律不予编写。
2. **补丁必须绑定版本**。同一锚点字符串在升级后的文件结构中可能落在不同位置。客户端 bundle 被整包覆写后，补丁的插入位置必须重新确认，而非沿用旧锚点。
3. **健康检查需校验真实产出，而非存在性标记**。故障期间探针报告 `HEALTHY` 而页面实际全白，说明「只检测引导标记」的检查方式存在盲区。
4. **根组件异常的影响面是全页**。定位「整页空白」类故障时，应优先排查根组件及其渲染路径，而非逐个子组件。
5. **文件级缺陷不需要卸载重装**。补丁为文件级改动，移除即可恢复；重装属于有效但代价更高的处置手段。
