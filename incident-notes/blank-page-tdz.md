# 客户端整页不渲染（TDZ 型 ReferenceError）

## 问题

客户端页面完全空白，无任何渲染内容，输入无响应（表现为会话被静默终止，而非报错弹窗）。宿主本体与服务正常。

**症状指纹**（用于快速识别同类故障）：

| 指纹 | 观测值 | 说明 |
| --- | --- | --- |
| 整页空白 | 渲染内容为空 | 非局部组件失效，而是根组件抛出异常 |
| 启动器日志特征行 | `[boot-monitor] cdp exception collected (evidence only)` | 出现在启动器日志中 |
| 页面探针长度异常 | 由健康值 2250+ 降至 44 | 关键量化判据（约 50 倍差距） |
| 健康检查误报 | 探针仍报告 `HEALTHY` | 该探针只校验引导标记是否存在，不代表页面渲染成功。**此行状态不可采信** |

「整页空白」应优先排查**根组件及其渲染路径**，而非逐个子组件：局部组件失效不会清空整页。

## 原因

自动化补丁流程把两行代码注入到了变量声明**之前**，形成 TDZ（暂时性死区）引用。注入后的真实代码形态：

```js
// 在根组件 AppFrame 的函数作用域内
}, [actions]);
/* local patch: keep the left sidebar collapsed on a narrow viewport */
if (narrow) layoutInfo.narrowExpanded = false;          // 引用 narrow
const narrow = viewport < SIDEBAR_AUTO_COLLAPSE;        // 同一作用域内后声明
```

`const` 声明在同一函数作用域内被提升但不初始化，初始化之前访问该绑定即抛 `ReferenceError: Cannot access 'narrow' before initialization`。异常发生在根组件的渲染路径上，根组件抛出后整棵渲染树无法挂载，页面呈全白。

**为什么语法检查未能拦截**：TDZ 属于运行期错误，代码在语法上完全合法，`node --check` 退出码为 0。补丁流程自带的语法闸门对此为**假绿**。

**为什么同一补丁此前未暴露该缺陷（推断，非实测）**：该补丁的锚点字符串在旧版本的文件结构中恰好落在无害位置；客户端 bundle 被整包覆写后补丁被洗掉，再次施加时落到了新结构的有害位置。**同一锚点字符串在不同版本的文件结构中可能成为缺陷。**

## 方法

修复方向：**退役肇事补丁并把补丁与版本绑定**，而不是在旧锚点上反复重试。

| # | 措施 | 回读结果 |
| --- | --- | --- |
| 1 | 肇事补丁退役 | 改名为 `RETIRED-apply-mobile-sidebar-patch.ps1.DO-NOT-RUN`（扩展名已不可误执行），保留回滚点 |
| 2 | 重新施加安全补丁 | 标记存在计 1 处，三行守卫存在 3 处，`node --check` 退出码 0 |
| 3 | 新增常驻自检脚本 | 实测输出「安全补丁 PRESENT / 退役补丁 absent / verdict CLEAN」 |
| 4 | 更新运维档案与补丁流程 | 已写入并回读 |

### 验证（顺序即优先级）

1. 抽取**打过补丁的真实源码片段**，配以 stub 实际执行（运行期验证，非静态推断）：
   - 保留那两行 → `THROWS: ReferenceError - Cannot access 'narrow' before initialization`
   - 删除那两行（对照组）→ `NO ERROR - rendered fine`
2. 页面探针长度回到健康区间。
3. 常驻自检脚本判决为 CLEAN。

### 回滚

- 恢复旧行为（不推荐）：将 `RETIRED-*.DO-NOT-RUN` 改回 `.ps1` 后执行 —— 该补丁即本次故障的成因。
- 补丁的生效条件：bundle 的 `rev` 值在服务端启动时计算，补丁需**重启服务**后才会被前端拉取。

## 结果

页面恢复渲染，探针长度回到健康区间，常驻自检脚本判决 CLEAN。

### 可迁移结论

1. **语法检查不能替代运行期验证。** `node --check` 通过不代表代码可运行；TDZ、未定义引用、类型错误均属运行期问题。凡是在 `const` / `let` 声明之前引用同名变量的补丁，一律不写。
2. **补丁必须绑定版本。** bundle 被整包覆写后，插入位置必须重新确认，不得沿用旧锚点。
3. **健康检查要校验真实产出，而非存在性标记。** 只检测引导标记的检查有盲区。
4. **文件级缺陷不需要卸载重装。** 补丁是文件级改动，移除即可恢复；重装代价更高。
5. **根组件异常的影响面是全页。**

### 已知限制

- 「旧版本未暴露该缺陷」的机制解释为**推断**，非实测：旧版对应文件已被升级覆写，无法回读验证。其余结论均为实测。
- 页面探针的盲区尚未修复（仍只校验引导标记），当前依赖独立自检脚本作为补偿控制。
- 客户端补丁会在本体升级 / 重装 / 插件升级后被覆写，升级后需重新施加安全补丁；**肇事补丁永不重新施加**。
