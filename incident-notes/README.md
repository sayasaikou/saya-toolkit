# incident-notes —— 故障复盘（症状 → 根因 → 判据）

这里放的是**真实故障的复盘**，写法固定：**症状指纹 → 定位过程 → 根因 → 修法 → 回滚点 → 教训**。
比"教程"有用得多的是：**下次怎么一眼认出来**。

## 复盘模板（建议照这个写）

```markdown
## 症状
（一句话 + 用户原话）

## 症状指纹（下次一眼认出来）
- 现象 1 / 现象 2 …
- ⚠️ 哪个"健康检查"在这种情况下**会骗人**（很重要）

## 定位过程
（关键证据：哪个日志的哪一行、哪个探针的哪个数值、时间戳怎么对上的）

## 根因
（机制层面说清"为什么会这样"，而不是"改了这个就好了"）

## 修法与验证
（改了什么 → 用什么**独立证据**验证 → 回滚点在哪）

## 教训（可迁移的）
1. …
```

**写作纪律**：
- **不确定就写"这是推断，不是实测"** —— 复盘的价值在于可信，不在于好看；
- **回滚点必须点名**（哪个文件、哪份备份、怎么退回去）；
- **失败的路也要写**：哪条路试过、为什么不通，省得下个人再走一遍。
