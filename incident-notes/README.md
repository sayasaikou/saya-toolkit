# incident-notes：故障复盘

本目录收录生产环境中实际发生的故障复盘。文档结构统一为：**现象与症状指纹 → 时间线 → 根因 → 证据链 → 修复与验证 → 回滚方案 → 经验教训 → 已知限制**。

此类文档的主要价值在于**同类故障的识别效率**：明确记录故障的表现特征与验证方式，避免重复排查。

## 目录

| 文档 | 主题 | 关键判据 |
| --- | --- | --- |

| [`session-format-change-breaks-plugins.md`](session-format-change-breaks-plugins.md) | 宿主升级后全部插件加载失败 | 会话日志格式发生大的版本变更，读取它的插件按旧结构解析并对 `undefined` 取值。判据：**配置文件全对、插件文件全在、boot 清单也无缺失**（即所有「静态检查」都是绿的），只有运行期解析炸掉 |

## 复盘文档模板

```markdown
## 1. 摘要

## 2. 现象与症状指纹
- 表现特征
- 需要注意的误导性健康检查（在何种情况下会给出错误结论）

## 3. 时间线
（时间戳与事件对应关系，须来自日志而非回忆）

## 4. 根因
（说明机制层面的原因）

## 5. 证据链
（关键日志、探针数据、命令输出）

## 6. 修复措施与验证
（修复内容与验证方式）

## 7. 回滚方案

## 8. 经验教训
（可迁移的结论）

## 9. 已知限制与未决项
```

## 编写规范

1. 不确定的结论须明确标注为推断，不得表述为已验证事实。
2. 回滚方案须写明具体文件、备份位置与恢复步骤。
3. 失败的尝试同样需要记录，包括尝试内容与失败原因，以避免重复投入。
4. 量化数据（时间戳、测量值、日志原文）应保留，这是文档可复核性的基础。
