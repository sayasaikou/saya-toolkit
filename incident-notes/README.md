# incident-notes：故障复盘

本目录收录生产环境中实际发生的故障复盘。文档结构统一为：**现象与症状指纹 → 时间线 → 根因 → 证据链 → 修复与验证 → 回滚方案 → 经验教训 → 已知限制**。

此类文档的主要价值在于**同类故障的识别效率**：明确记录故障的表现特征与验证方式，避免重复排查。

## 目录

| 文档 | 主题 | 关键判据 |
| --- | --- | --- |
| [`blank-page-tdz.md`](blank-page-tdz.md) | 页面整体不渲染 | 补丁引用了尚未初始化的 `const` 绑定，产生 TDZ 错误；语法检查无法检出（运行期错误），表现为页面完全空白，页面探针返回长度由约 2250 降至约 44 |
| [`invisible-console-window.md`](invisible-console-window.md) | 无窗口启动器仍创建控制台窗口并抢占焦点 | 可执行文件被编译为控制台子系统；`CREATE_NO_WINDOW` 仅作用于子进程，不作用于自身。通过窗口枚举探针将「窗口出现、焦点抢占、窗口关闭」三个事件与计划任务启动时间精确对应 |
| [`bsod-triage.md`](bsod-triage.md) | 蓝屏与硬冻结排查 | 出现多个不同的 bugcheck 代码并伴随无转储的强制关机，判定为平台级不稳定而非单一驱动缺陷。排查顺序：清除第三方内核驱动残留 → 配置转储与手动触发崩溃 → 24 小时观察窗口 |

## 复盘文档模板

```markdown
## 1. 摘要

## 2. 现象与症状指纹
- 表现特征
- 需要注意的误导性健康检查（在何种情况下会给出错误结论）

## 3. 时间线
（时间戳与事件对应关系，须来自日志而非回忆）

## 4. 根因
（说明机制层面的原因）

## 5. 证据链
（关键日志、探针数据、命令输出）

## 6. 修复措施与验证
（修复内容与验证方式）

## 7. 回滚方案

## 8. 经验教训
（可迁移的结论）

## 9. 已知限制与未决项
```

## 编写规范

1. 不确定的结论须明确标注为推断，不得表述为已验证事实。
2. 回滚方案须写明具体文件、备份位置与恢复步骤。
3. 失败的尝试同样需要记录，包括尝试内容与失败原因，以避免重复投入。
4. 量化数据（时间戳、测量值、日志原文）应保留，这是文档可复核性的基础。
