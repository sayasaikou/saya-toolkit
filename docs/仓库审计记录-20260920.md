## 三、发现与处置

### 3.1 已修复：`stress-kill.ps1` 的日志路径

- **问题**：日志路径以单引号字符串赋值（`'$env:DSH_HOME\stress-kill.log'`）。在 PowerShell 中单引号不做变量展开，因此程序会在当前工作目录下创建名为 `$env:DSH_HOME` 的目录，且路径与用户预期不符。
- **成因**：路径替换脚本跨语言套用，与 Python 文件中的同类问题（`comfygen.py` 的 `$env:DSH_AI`）同源。
- **处置**：改为参数 `-LogFile`，默认值为 `Join-Path $env:TEMP 'stress-kill.log'`；提交 `a408bdf`。

### 3.2 已确认无效（检查工具的误报，非仓库问题）

- 首页 README 中指向各目录的链接（`dsh-handoff/` 等）在检查脚本中报为失效，原因是该脚本只比对文件、不比对目录。经确认这些目录在仓库中均存在，链接有效。

1. 两个仓库当前**未发现凭据泄露或个人信息残留**，公开仓内容与文档一致，脚本在干净环境中可运行。

3. **已知限制**：私有仓按设计包含本机档案与工具配置，其安全性依赖仓库的可见性设置与访问令牌的保管；一旦需要调整可见性，应先执行一次凭据扫描。
