# snapshot-tools：环境快照与还原

把一份应用主目录拍成**可按日期回退的完整存档**，并在需要时整体还原。

与 `config-backup/` 的分工：那边是「把配置镜像到 git 仓库，用于日常小步回退」；这边是「把整个环境拍成一份可整体回滚的存档」，用于换版本、大改动之前留锚点。

## 解决的问题

| 问题 | 朴素做法 | 本工具 |
| --- | --- | --- |
| 存档太大 | 每天整份打包 → 体积线性增长 | 未改动的文件**硬链接**到上一份 ⇒ 每天只为真正变化的字节付费（实测约 300 MB/天） |
| 依赖树无法可靠还原 | 一起打包 → 存进去的是一棵带绝对路径链接、跨机器跑不起来的树 | 依赖树**有意排除**，还原时用包管理器重新安装 |
| 还原会丢凭据 | 整目录覆盖 → 存档里是拍快照那台机器的凭据 | 明确列出「必须保留本机版本」的文件，交换后拷回 |
| 还原失败把人锁在门外 | 先删新目录再改名回来 → 删到一半失败，好的存档停在旁边目录 | 全程用**改名**而非递归删除；失败则把坏的那份改名到一边、原目录改名回来 |
| 两个还原撞车 | —— | 还原锁（写入 PID），检测到另一个还原进程存活即拒绝运行 |

## 用法

```powershell
# 拍快照（可放到每日计划任务）
pwsh -NoProfile -File .\snapshot-create.ps1 -Target 'D:\snapshots'
pwsh -NoProfile -File .\snapshot-create.ps1 -Target 'D:\snapshots' -Keep 14 -KeepMonthly 6

# 还原：默认干跑，什么都不写
pwsh -NoProfile -File .\snapshot-restore.ps1 -Target 'D:\snapshots'
pwsh -NoProfile -File .\snapshot-restore.ps1 -Target 'D:\snapshots' -Snapshot 2026-01-31 -Apply -Force
```

`snapshot-create.ps1` 退出码：`0` 成功，`2` 主目录不存在。
`snapshot-restore.ps1` 退出码见脚本头部（`2` 无此快照 / `3` 快照不完整 / `4` 服务在跑且未加 `-Force` / `5` 失败并已尝试回滚 / `6` 另一个还原正在运行）。

## 设计与取舍

**为什么用硬链接而不是压缩包。** 压缩包既慢又大，而且无法表达「这个文件没变」——每次运行都要重写全部内容。硬链接让上一份快照成为「没变的那部分」的实际存储，同时每份带日期的目录**看起来仍是一棵完整的树**，任何走目录的工具都不会察觉差异。删除一份快照只删掉那些名字，数据只要还被别的快照链接就依然存在，所以轮转是安全的。

**为什么依赖树必须排除。** 包管理器建立的模块树里含绝对路径链接与平台相关的构建产物。把它塞进快照，还原出来的是一个**看起来完整、实际跑不起来**的树——而且失败现象是启动即崩，很难联想到快照本身。所以快照排除它，还原脚本重装它。重装**不能加**强制/清理标志：那会覆盖包管理器自己维护的模块链接，产出一棵之后每次启动都失败的树。

**为什么「必须保留本机版本」的文件要单独列。** 快照里存的是**拍快照那台机器**的凭据与设置。整体覆盖会把别人的凭据写到你这台机器上——大概率表现为「服务起不来」或「登录状态丢失」，而不是一句清晰的报错。`-KeepFiles` 就是这份清单。

**为什么还原用改名而不是删除。** 早期设计是「删掉新目录，再把停放的旧目录改名回来」。这个顺序在一次真实演练里失败了：目录里还有联接点或被占用的文件时，递归删除会中途放弃，结果是**坏的那份还活着、好的那份停在旁边的目录里**——比不还原更糟。改名即使在有锁的情况下也能成功，所以回滚路径改成：把坏的那份改名到一边，把停放的原始目录改名回来。

**为什么还原前要检查服务是否在运行。** 在服务运行期间替换它自己的文件，是这个工具最容易造成的自伤：它可能正在写配置、持有锁、或者把你刚换进去的文件又覆盖回去。默认遇到运行中的服务就中止，要求显式 `-Force`。

## 已知限制

1. **硬链接需要同一卷。** 快照目标与主目录不在同一个卷时，脚本会自动退化成真复制（正确，但慢且占空间）。脚本在每次复制失败时都会在日志里体现，不会静默。
2. **平台绑定。** 计划任务、符号链接/硬链接语义、`robocopy`、`powercfg` 与 WMI 显示器查询都是 Windows 特性。
3. **快照不含依赖树**，所以从一个快照还原后必须能装依赖（需要网络或本地包缓存）。
4. **「未变化」的判据是长度 + 写入时间（UTC）**。同长度同时间戳但内容不同的文件会被漏掉——这种情况在正常文件系统操作下不出现，但用工具手工回拨时间戳可以伪造出来。
5. **轮转只删自己生成的日期目录**；主目录里其他内容（README、脚本、日志）一律不碰。
6. **陈旧文件只报告、不删除。** 因为复制只会新增或刷新，任何从主目录删掉的东西都会留在旧快照里，还原时会复活它。脚本把这类顶层文件列进日志与清单（`staleTopLevel`），由人决定怎么处理——自动删等于让工具去猜哪些文件是垃圾。
