# saya-toolkit

面向 Windows 环境的 AI 助手工程实践工具集。本仓库收录若干**在真实生产环境中长期使用**的组件，涵盖跨会话状态交接、Windows 自动化约束的绕行方案、硬件压力测试与监控、以及本地生成式模型的批量出图流水线。

所有内容均来自实际运维与开发过程，附带可复核的实测数据、失败方案记录与回滚方案。仓库不附带任何模型权重或第三方素材。

## 目录结构

| 目录 | 内容 | 解决的问题 |
| --- | --- | --- |
| [`dsh-handoff/`](dsh-handoff/) | 跨会话交接机制（状态文件 + 模板 + 核对脚本） | 助手会话之间的上下文不连续与人工交接漂移 |
| [`vision-tools/`](vision-tools/) | 多模型视觉交叉验证流水线（算法证据 → 多模型并排 → 自动分歧 → 裁图复检 → 带证据等级的报告） | 单个视觉模型答一次就下结论不可靠：模型「一致」不等于「正确」，自报坐标可能是编的，看不清与没有会被混为一谈 |
| [`win-agent-tools/`](win-agent-tools/) | 无窗口进程启动器、HTML 渲染截图、环境更新自检 | 计划任务创建控制台窗口并抢占前台焦点；自动化脚本缺少网页渲染能力；依赖更新靠人工记忆 |
| [`config-backup/`](config-backup/) | 配置备份与还原、健康探针、**保留策略三件套**（本地快照 / 云端历史 / 定时快照） | 改配置前没有可回退的锚点；备份只增不减最终撑爆磁盘；本体是不是健康的靠猜 |
| [`snapshot-tools/`](snapshot-tools/) | 环境快照的拍摄与还原（默认干跑、写入前自动另存） | 需要一份可整体回退的「当前环境存档」，且还原必须可预防、可演练 |
| [`thermal-monitor/`](thermal-monitor/) | Afterburner 共享内存读取、双烤一键监控 | 无法在不安装驱动的前提下批量获取传感器数据；压力测试缺乏自动化收尾与安全边界 |
| [`blender-headless/`](blender-headless/) | Blender 无头渲染脚本集说明 | 批量多视角渲染与材质问题定位依赖手工操作 |
| [`comfy-pipeline/`](comfy-pipeline/) | ComfyUI 批量出图与提示词生成 | 多底模调用方式不统一；生成结果趋于同质化（固定站姿、背景单一） |
| [`troubleshooting/`](troubleshooting/) | 故障记录（问题 / 原因 / 方法 / 结果） | 同类故障的识别与定位成本 |
| [`docs/`](docs/) | 收录范围、脱敏规则、跨引擎与脚本约束、依赖升级模式、仓库审计记录 | 说明哪些内容适合公开、哪些必须保留在私有环境；把踩过的平台坑固化成规则 |

## 组件说明

### vision-tools

一条命令走完整个识图流程，并且**强制给每个结论标证据等级**（确证 / 推断 / 存疑）：

```
L0 算法证据   尺寸 / 主色 / 本地 OCR        —— 不经模型，不会幻觉
L1 多模型并排 多个视觉后端各自独立作答
L2 自动分歧   程序化比对，逐项判「一致 / 兼容 / 冲突」
L3 自动复检   对冲突项裁图放大 → 重问 → 取色
L4 汇总报告   带证据等级，被时间预算砍掉的步骤显式标注为「未跑」
```

设计上的核心取舍：**能算的绝不问模型**（尺寸、颜色、印刷体文字、两图差异交给本地工具）；**「确证」只代表多源一致、不代表正确**（实测两个模型异口同声给出同一个错误答案，本地取色才是判据）；**静默丢失比判错更危险**（被预算砍掉的检查项必须显式列出，不能让它看起来像「检查过了、没问题」）。未经配置的后端会被自动跳过，因此零 API Key 也能跑 L0 + 本地层。

### dsh-handoff

采用「单一数据源 + 机器渲染 + 每次实测」的方式维护跨会话状态。维护者只更新一份状态文件，由脚本负责核对环境实际状态（进程、计划任务、文件时间戳、引用路径存活情况）并渲染成交接文档，输出带有核对时间戳，使「已核对」具备可追溯凭据。

### win-agent-tools

- `run-hidden.cs`：将启动器编译为 GUI 子系统可执行文件，由它调用目标命令。相比 `-WindowStyle Hidden` 与 VBScript `WScript.Shell.Run` 方案，可从根本上避免控制台窗口的创建。
- `html-shot.ps1`：调用系统自带浏览器内核渲染 HTML 并输出 PNG，输出具备确定性（相同输入连续两次渲染的 SHA256 一致），可用于交付前的视觉验收。
- `update-check.ps1`：会话开始时的依赖更新自检 —— **只查不升**。它存在的理由是一次「会自己动手升级宿主」的插件把环境改坏了：这类组件的失败模式是静默破坏他人的文件，比装不上危险一个量级。

### config-backup

- `sync.ps1` / `restore.ps1`：把配置目录按白名单镜像进一个私有 git 仓库，以及从仓库还原回来。**还原默认干跑**，`-Apply` 才写，且覆盖前先把现有文件另存为 `*.bak-<时间戳>`。
- `health-check.ps1`：不依赖宿主自身的健康探针。它会**自动识别部署形态**（单进程桌面客户端 / 独立启动器 + 外部服务），因此不会出现「探针写的是旧形态、于是在新形态下永久报警」这种狼来了式误报；无法执行的检查报 `n/a` 而不是失败。
- **保留策略三件套** —— 备份只增不减会撑爆磁盘，而「删哪些」比「备份哪些」更容易出错：
  - `prune-local-backups.ps1`：按「出生时间」（取创建时间与写入时间中较晚者）清理过期快照，带白名单。**为什么不能用写入时间**：复制会保留源文件的写入时间，于是今天刚做的回滚点会带着三天前的时间戳，naive 的年龄判断会**先删最新的那个**。
  - `prune-snapshots.ps1`：只清理名字形如 `yyyy-MM-dd` 的目录，其余（README、启动器脚本、日志）一律不碰。
  - `archive-old-versions.ps1`：把备份仓库的 git 历史压减到最近 N 个版本。**专门写成了不会让分支指针与工作树脱节**的顺序（先提交归档清单 → 用 `commit-tree` 重放 → `update-ref` 带旧值守卫 → `read-tree` 同步 → 校验文件清单 → 失败整体回退），并且会把被移除的 commit 清单落成一份文档。
  - `maintenance-daily.ps1`：把上面三件事串成一次运行并写一份日志，每个子任务的 `VERDICT` 行被提取进同一条日志 —— 因为**每晚都失败的任务和每晚都没事可做的任务，看起来完全一样**。

### snapshot-tools

- `snapshot-create.ps1`：把当前环境状态拍成一份带日期的存档（配置、清单、版本信息）。
- `snapshot-restore.ps1`：从存档还原。**默认干跑**，写入前逐文件另存，且会先检查服务是否在运行 —— 在服务运行中替换它的文件是这个工具最容易造成的自伤。

### thermal-monitor

通过 MSI Afterburner 暴露的共享内存（MAHM）读取传感器数据，无需安装驱动或依赖 SDK，可获取 91 项指标（温度、功耗、频率、占用率及功耗墙状态）。配套脚本提供双烤流程的自动采样、收尾与安全中断。

### comfy-pipeline

为 ComfyUI 提供统一的命令行入口（多底模族、批量生成、结构化输出），并提供基于角色档案与场景池的提示词随机生成，用于规避模板化输出。

## 实证结果

每个组件都在真实环境长期使用过。下面是可复核的实测结论（含**失败方案的记录** —— 结论是怎么被推翻的，比结论本身更有参考价值）。

| 组件 | 实测结论 |
| --- | --- |
| **vision-tools** | ① **两个独立视觉模型异口同声给出同一个错误答案**（把一件衬衫说成金色），本地取色证明是深蓝近黑 `#272948`（占 62%）⇒ 颜色类判据必须以算法为准<br>② **模型自报的坐标可能是编的**（把领口定位到脸上；声称依据区域 x=200–300，而裁剪块总宽只有 260）⇒ 定位改用独立的定位接口<br>③ 首次回归基线：dashscope **76.2%** / zhipu **74.4%**（26 条真值）—— OCR 类满分，**精细外观类仅 57%**<br>④ 单张 900×400 图 ≈ **338 image tokens** ≈ 0.0006 元 |
| **win-agent-tools** | ① `run-hidden.cs` 方案下**控制台窗口零出现**（`-WindowStyle Hidden` 与 VBScript 方案都会残留）<br>② `html-shot.ps1` 相同输入连续两次渲染 **SHA256 一致**（可作交付前验收判据）<br>③ 计划任务中 `run-hidden.exe` **不能直接启动 Store 版 pwsh**（`LastTaskResult=2`、日志一行不写）⇒ 需经 `.cmd` 中转 |
| **config-backup** | ① 「按写入时间清理」会**先删掉最新的回滚点**（复制保留源文件写入时间）⇒ 改用创建/写入时间的**较晚者**<br>② 云端仓库压减到最近 20 个版本，实测**文件清单校验通过、被移除的 commit 有据可查**<br>③ 探针在「单进程桌面客户端」形态下不误报（自动识别部署形态） |
| **dsh-handoff** | 核对脚本每次实测 6 类环境事实（进程 / 计划任务 / 文件时间戳 / 引用路径存活 / 插件加载 / 指纹时间），输出带时间戳 ⇒ 「已核对」可追溯 |
| **thermal-monitor** | 通过 MAHM 共享内存读到 **91 项指标**，无需驱动或 SDK；双烤实测采样 449 点，定位到瓶颈为厂商功耗墙（GPU 172 W / CPU 65 W） |
| **comfy-pipeline** | 本机实测速度：Flux 1024²/4 步 ≈ **14.1 s** ｜ Illustrious 832×1216/28 步 ≈ **14.1 s** ｜ Anima turbo 1024²/6 步 ≈ **12.1 s** |
| **snapshot-tools** | 默认干跑 + 写入前逐文件另存；还原前**先检查服务是否在运行**（服务运行中替换其文件是本工具最易造成的自伤） |
| **平台坑（docs/）** | 跨引擎实测：`[int] + '/'` **两个引擎都炸**；中文只在「字符串里奇数个汉字 + 紧跟 ASCII 元字符」时才真炸（注释里的中文安全）；`.bat` 的 LF 换行会让 cmd **吃掉下一行首字符** |

### 被推翻的方案（同样重要）

| 方案 | 为什么放弃 |
| --- | --- |
| 让模型自报边界框来定位 | 实测两次失败：5000×5000 的图上把叶子报成主体；另一张干脆读不出坐标 ⇒ 改成「画带编号的格子，让模型说在哪几格」 |
| 提示词驱动「模型自己记录状态」 | 机械性动作交给模型自觉会失败（它当成可选建议）⇒ 改成事件钩子硬编码 |
| 对整图直接提问细节 | 4 MP 图缩到模型输入尺寸后细节合并，模型会"编"（把两层衣服说成一件）⇒ 必须先裁出放大 |
| AI 超分放大裁块 | 大块超分产出 38.8 MB 无法使用的巨图、且更糊 ⇒ **只在小块（信息少）时用**；小块实测清晰度提升 **18.6 倍** |

## 复现须知

1. 脚本中的路径通过环境变量（`$env:DSH_HOME`、`$env:DSH_WORKSPACE`、`$env:DSH_AI`、`$env:DSH_SNAPSHOT_DIR` 等）配置，或在命令行传参覆盖，首次使用需按实际目录调整。**凡涉及删除的脚本（保留策略、快照清理）一律要求显式传入根目录**，不给本机默认值——默认值写错就会删错树。
2. 面向计划任务的 PowerShell 脚本应为纯 ASCII，或写成带 UTF-8 BOM 的中文。Windows PowerShell 5.1 会把无 BOM 的 UTF-8 文件按 ANSI 解析：中文变成乱码只是轻的 —— **当字符串里汉字个数为奇数、且其后紧跟引号等 ASCII 字符时，那个字符会被当成汉字尾字节吞掉，导致整个脚本解析失败、一行都不执行**（注释里的中文不受影响）。判据与实测对照见 [`docs/powershell-cross-engine-guardrails.md`](docs/powershell-cross-engine-guardrails.md)。
3. **写脚本前先读** [`docs/windows-scripting-pitfalls.md`](docs/windows-scripting-pitfalls.md)：路径与参数、计划任务、编码、文件与进程五类坑都是实测记录，其中「内置只读变量不能当参数名」（例如把参数命名为 `$Home`）的失败模式尤其隐蔽 —— 函数直接返回空值，脚本继续跑并给出错误结论，而不是报错停下。
4. `vision-tools/` 需要 Python 3.10+ 与 `Pillow`；多模型后端与本地 OCR 层都是可选的，**没配 Key 的后端会被自动跳过**，零配置也能跑本地算法层。其 `testset/images/` 有意不附带图片，打分前需自备（见该目录 README）。
5. 文档中的实测数据均来自特定测试机，不同硬件配置下结论可能不同，相关机型信息已在各文档中说明。
6. 本仓库组件依赖 Windows 平台（计划任务、MAHM 共享内存、PE 子系统行为、硬链接语义均为平台特性）。
