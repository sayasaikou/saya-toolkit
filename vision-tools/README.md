# vision-tools：多模型视觉交叉验证工具链

单个视觉模型答一次就下结论，会出错。本工具链把「问一次模型」拆成一条带证据等级的流水线：能算出来的交给本地算法，必须问模型的就并排问多个，出现分歧自动裁图放大复检，最后按 **确证 / 推断 / 存疑** 三级输出报告。

本工具链已在长期运行的 DSH（DeepSeek Harness）环境中用于角色外观建档、图表细节核对与 OCR 回归测试；本仓库版本已移除本机路径、账号与个人信息。文中保留的实测数据与失败记录都来自真实使用，未作删改。

## 要解决的问题

| 现象 | 实测例子 | 本工具链的应对 |
| --- | --- | --- |
| 单模型答一次就下结论 | 同一次提问换一个模型，答案就可能相反 | L1 并排问多个后端，L2 自动比对，L3 对冲突项复检 |
| **模型「一致」不等于「正确」** | 两个模型异口同声说衬衫前襟的扣子是**金色**；PIL 对该区域取色为 `#272948`（深蓝近黑）占 62%，衬衫本体是浅白 `#C8BCD0` —— 两个模型一起错 | L0 / L3 的算法证据（尺寸、取色、OCR）不经模型，与模型答案并列；像素证据与模型冲突时以像素为准 |
| 模型自报的坐标可能是编的 | 把领口定位到脸上；声称「依据在 x=200–300」，而该次裁剪块的总宽只有 260 像素 | 坐标只在同一次调用内使用、跨调用不复用；复检支持 `--region x1,y1,x2,y2` 手动指定区域，绕开模型定位 |
| 静默丢失 | 长图跑到被超时掐断，报告里没有任何记录，看起来像「查过了」 | 被预算砍掉的步骤在报告里标成 **「未跑·超预算」**，既不算「看不清」也不算「否」 |
| 模型复读 | 同一句话吐 24 遍，被交叉验证当成 24 条独立观察，凭空多出假观察项 | 复读折叠：检出后折叠为一条，并标注 `复读 xN 已折叠` |

## 四层架构

| 层 | 做什么 | 谁来做 |
| --- | --- | --- |
| **L0 确定性工具** | 图像尺寸、主色量化、本地 tesseract OCR | 本地算法，不经模型，不会幻觉 |
| **L1 多模型并排** | 同一个问题分别问多个后端，各自独立作答（没配 Key 的后端自动跳过） | 云端 / 本地视觉模型 |
| **L2 自动分歧检测** | 把 N 份答案交给裁判模型，输出结构化 JSON：一致 / 冲突 / 孤证 | 裁判模型 |
| **L3 自动复检** | 对每一个冲突项：裁图 → 放大（长边拉到 2000px，最多 3 倍）→ 重问 → PIL 量化取主色 | 模型 + 本地算法 |
| **L4 汇总报告** | 逐项标注 `[确证]` / `[推断]` / `[存疑]`，附算法证据、耗时与被跳过的步骤 | 程序生成 |

证据等级的判据（写死在 `eye.py` 里，不允许含糊）：

- `[确证]` —— 多模型一致，或复检后收敛，或有算法证据支持；
- `[推断]` —— 只有单一来源提到（可能是幻觉，也可能是别的模型漏看了）；
- `[存疑]` —— 模型之间矛盾，且复检后仍未收敛。

## 文件组成

| 文件 | 用途 |
| --- | --- |
| `eye.py` | **默认入口**：L0 → L1 → L2 → L3 → L4 一条命令走完 |
| `eyeprobe.py` | 公共模块与独立工具：多后端调用、分块、复读折叠、裁判仲裁 |
| `vrecheck.py` | 分歧项复检：定位 → 裁图放大 → 重问 + PIL 取色 |
| `vscore.py` | 对真值集打分（LLM 交叉裁判，宽松上界） |
| `doctor.py` | 五层自检：依赖 / tesseract 与语言包 / Key / Ollama / 真值集 |
| `layered.py` | 服装分层解析：分件 → 逐件细化 → 装配关系 → 穿衣序列 |
| `schemas/character.json` | 通用角色外观答题卡（59 项，模板无真值，适用任意角色图） |
| `testset/truth.json` | 真值回归集（4 图 27 条，带三级可信度字段） |
| `使用判据.md` | 方法论与铁律完整版：每条都由一次实测事故换来 |

## 安装与配置

依赖：

- Python 3.10 及以上；
- `pip install Pillow`。

可选组件（缺了不影响主流程，只是少一层证据）：

- **tesseract 5.x** —— 用于 L0 的本地 OCR。查找顺序：环境变量 `TESSERACT_EXE` → PATH 里的 `tesseract`。都没有时只跳过 OCR 一步，其余照跑。
- **Ollama + `qwen2.5vl:7b`** —— 本地离线层，不消耗额度，适合批量筛图。

后端与各自的 Key 环境变量（**没有配 Key 的后端会被自动跳过，不需要全部配齐**）：

| 后端名 | 模型 | 环境变量 | 说明 |
| --- | --- | --- | --- |
| `dashscope` | `qwen3-vl-plus` | `DASHSCOPE_API_KEY` | 默认启用，速度与准确度较均衡 |
| `omni` | `qwen3.5-omni-plus` | `DASHSCOPE_API_KEY` | 与 `dashscope` 互补，建议一起上 |
| `zhipu` | `glm-4.6v-flash` | `ZAI_API_KEY` | 免费额度，高峰期可能 429；默认不启用 |
| `doubao` | `doubao-seed-2-0-pro` | `ARK_API_KEY` | 端点已接好，模型档位需按账号确认 |
| `ovh` | 匿名端点 | 不需要 | 兜底，限速 2 次/分钟 |
| `ollama` | `qwen2.5vl:7b` | 不需要 | 本地离线，`http://127.0.0.1:11434` |

Key 的读取顺序是**先读 Windows 用户环境变量（`HKCU\Environment`），读不到再退回进程环境变量** —— 这样在已经开着的终端里新设的 Key 不用重开窗口。

`doctor.py` 会把这些逐项测一遍，出问题先跑它：

```powershell
python doctor.py           # 静态检查（不花钱、不调模型）
python doctor.py --live    # 额外把每个后端实调一次（消耗额度）
```

## 用法

### 默认入口 `eye.py`

```powershell
# 自由描述：列出图中显著元素、相对位置与颜色
python eye.py photo.png --preset diff --out 报告.md

# 外观建档：逐项问领口 / 露肩 / 裙层 / 图案朝向 / 鞋袜 ……
python eye.py photo.png --preset outfit --models dashscope,ollama --out 报告.md

# OCR：逐字转写图中文字
python eye.py scan.png --preset ocr

# 结构化答题卡：模型按固定 JSON 作答，程序自己比对，全程不用裁判
python eye.py photo.png --schema character --out 报告.md

# 只跑 L0~L2，不做 L3 复检（快，但分歧不会被收敛）
python eye.py photo.png --no-recheck

# 大图：放宽时间预算、调低降采样上限
python eye.py big.png --budget 900 --max-side 3000
```

`--schema` 的取值来自 `schemas/*.json` 与 `testset/truth.json` 里的图片 `id`：取到通用卡（如 `character`）时只出描述；取到真值卡（如 `ref-a`）时会额外按真值自动打分。

### 其余脚本各在什么时候用

| 脚本 | 什么时候用 |
| --- | --- |
| `eyeprobe.py` | 想单独换问题、换模型、或按横带分块问时（`eye.py` 已内含这套逻辑） |
| `vrecheck.py` | 某个具体争议项说不清时：`python vrecheck.py 图.png --item "围裙上的图案是什么"`；定位不准就加 `--region x1,y1,x2,y2` |
| `vscore.py` | 改过模型、prompt 或真值集之后做回归：`python vscore.py --models dashscope,zhipu --out 回归.md` |
| `doctor.py` | 任何时候觉得「有哪一层坏了」，先跑它，别靠猜 |
| `layered.py` | 服装结构乱、模型把裙摆层数说成「穿了三件」时，按 大件／配件 两分法逐层解析 |

## 关键设计取舍

**1. 被预算砍掉的步骤必须点名，不能静默消失。**
报告里被跳过的步骤标成「未跑·超预算」。它**既不算「看不清」也不算「否」** —— 静默丢失比判错更危险：判错至少还有一条能被质疑的结论，丢失则什么都不剩，而报告看起来像查过了。

**2. 全局时间预算 + 入口降采样。**
`--budget`（默认 420 秒）是整条流水线的墙钟上限，`--max-side`（默认 2000）在入口把长边压下来。实测一张 2700×5400（14.6 MP）的长图：改造前跑满 9 分钟什么都没产出（180 秒 socket 超时 × 3 次重试 = 单个后端 540 秒，再乘上每个块、每个复检项）；加上这两项之后 **34 秒出报告**。整图缩过会丢细节 —— 要抠小目标请先裁块放大，别指望整图。

**3. 超时不重试。**
超时是终止性失败：后端对**这个体积的负载**就是太慢，重试只是把等待乘以次数。这一条是上面那 9 分钟黑洞的最大成因。相反，`429 / 500 / 502 / 503 / 504` 这类瞬时故障会退避重试。

**4. 复读必须折叠。**
模型把同一句话吐 24 遍，是故障不是描述。不折叠的话，交叉验证会把它当成 24 条独立观察，凭空多出一个「多模型都看到了」的假观察项 —— 而且是**看起来最可信**的那种假。折叠后在报告里标注 `复读 xN 已折叠`，不隐藏。

**5. 严格下界与宽松上界，两个分数不是一回事。**
`eye.py --schema` 用程序比对，只认字面接近（精确 / 包含 / 字符集重叠 / 字面相似），**措辞不同但意思相同的也会判错**，是**严格下界**；`vscore.py` 用 LLM 交叉裁判判「实质一致」，是**宽松上界**。真实水平在两者之间 —— 别把两个数放在一起比，也别把任一个当「能力值」。

## 已知限制

1. **模型随机性大于判据差异。** 同一张图隔 3 分钟跑两次，措辞就会变，分数浮动 1~2 项。所以**单次分数不能当「能力」读**，要看趋势和多次运行的包络。
2. **问法能修「用词」，修不了「看错」。** 换提问方式可以让模型把「荷叶边」说成「波浪形花边」，但它把翻领看成立领、把看不见的袜口说成短袜，换多少种说法都一样。看错要靠像素证据或人工裁夺。
3. **左右方向与形状判断是模型弱项。** 画面侧与角色自身侧经常混用；细长形状容易被归成另一种东西（鳍状耳被答成猫耳）。涉及左右的结论需要显式指定参照系，并优先采信算法或人工判定。
4. **小目标必须先裁出来放大再问。** 目标小于全图 5%（扣子、花纹、小字），或问的是颜色、个数、朝向时，整图问等于没问。
5. **真值也会错，但不能一律怀疑真值。** 真值集带三级可信度字段（`adjudicated` 人工裁定 / `verified` 逐条质证过 / `selfmade` 合成图绝对真值）。当两个独立模型同时反对一条真值时先怀疑真值，但要有独立证据才能改。
6. **真值集里的参考图未随仓库附带。** 图片按 `testset/images/` 下的相对路径引用，请自备同名图片，或直接修改 `testset/truth.json` 里的 `path` 字段。没有图片时 `--schema ref-a` 会报找不到文件，其余功能不受影响。
